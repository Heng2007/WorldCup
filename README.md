# World Cup Match Predictor

Predicts the outcome of an international football match — **Win / Draw / Loss** from the
home team's perspective — using a logistic regression model trained on historical
international results, blended with current-cycle form pulled from the
[football-data.org](https://www.football-data.org) API.

World Cup is too fun to watch, I am not satisfy with just watch the games. Therefore, I propose a project to have more fun during the World Cup.

## How it works

```
football-data.org API ──┐
                        ├──> feature engineering ──> LogisticRegression ──> Win/Draw/Loss
historical results CSV ─┘
```

Each match is reduced to six features:

| Feature | Meaning |
| --- | --- |
| `home_avg_goals` | Goals the home team scores per match, at home |
| `away_avg_goals` | Goals the away team scores per match, away |
| `home_avg_conceded` | Goals the home team concedes per match, at home |
| `away_avg_conceded` | Goals the away team concedes per match, away |
| `head2head_adv` | Home team's historical win rate in this exact fixture |
| `neutral_index` | 1 if played at a neutral venue, 0 otherwise |

At prediction time the four scoring averages are a **50/50 blend** of all-time historical
form and current-cycle form, so a team that has changed a lot recently isn't judged purely
on its 1950s record.

The classifier is `LogisticRegression(C=100, class_weight="balanced", solver="lbfgs")`.
`class_weight="balanced"` is there because draws are much rarer than wins or losses in the
training data.

## Known limitations

- **Target leakage in `head2head_adv`.** The feature is computed across the entire dataset,
  including the row it describes — so each match's own result is folded into its own
  feature. The four scoring averages have a milder version of the same problem: they're
  computed over all rows *before* the train/test split, so test-set outcomes influence
  training features. Any accuracy figure from the current pipeline is therefore optimistic.
  The fix is time-aware features — compute each average only from matches played *before*
  the match being predicted — and fitting any scaler inside a `Pipeline` on the training
  split alone.
- Logistic regression assumes the features relate linearly to the log-odds of each outcome,
  which is a strong assumption for football.
- No notion of squad quality, injuries, player-level data, or tournament stage.
- Team names must match the source data exactly (`"Canada"`, not `"canada"`).

## Setup

```bash
git clone https://github.com/Heng2007/WorldCup.git
cd WorldCup
python3.13 -m venv .venv           # Python 3.11+ required
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

An API key is only needed to refresh the current-cycle data. Get a free one at
football-data.org, then:

```bash
cp .env.example .env               # then paste your key into .env
```
